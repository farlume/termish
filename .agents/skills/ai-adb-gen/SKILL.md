# ai-adb-gen（AI 生成 Android UI 测试用例）

> 通用技能：AI 通过 adb 对 Android 应用做黑盒 UI 自动化测试——**用例生成**。
> 不绑定任何项目——项目特定内容（页面/用例/断言）在项目根的 `.aiadb-test/` 目录。
> 双份部署：用户级 `~/.agents/skills/`（本机可用）+ 项目级 `.agents/skills/`（随仓库）。

## 调用形式（重要）

```
ai-adb-gen <中文场景描述>    # 按需生成指定场景的测试用例（推荐日常用法）
ai-adb-gen                    # 全量生成：对照整个页面清单补齐所有场景
```

场景描述用中文自然语言，例如：

- `ai-adb-gen 会话场景` → 会话列表/多 tab/会话生命周期管理
- `ai-adb-gen 设置页` → 设置各分组与二级页
- `ai-adb-gen 新增主机` → 主机编辑页 CRUD
- `ai-adb-gen 终端键盘` → 终端页工具栏/快速命令

**场景定向模式（带参数）必须做到**：

- 只生成该场景对应的用例组，不铺开全项目、不生成无关场景
- 先检查 `cases/` 已有覆盖：已覆盖的不重复造轮子，只补缺漏（增量更新对应组）
- 产出时明确说明：**新增了哪些用例、跳过了哪些（已有覆盖）**，并提示执行方式
  （如 `ai-adb-run <组字母>`）

**全量模式（无参数）**：按下方「全量流程」对照页面清单逐页补齐。

## 适用范围与拒绝规则（容错机制）

本技能**仅适用于 Android 项目**（含 KMP / Compose Multiplatform 的 android target）。

执行前必须做**项目类型检查**（缺一即拒绝）：

| 检查 | 通过条件 |
|------|----------|
| AndroidManifest | 项目内存在 `AndroidManifest.xml`（任意模块） |
| Android 构建 | `build.gradle(.kts)` 有 `android` block / `applicationId`，
  或 KMP 的 `androidTarget()` / `androidLibrary()` |

**拒绝规则**：
- 任一检查不通过 → 输出 `❌ ai-adb-gen 仅适用于 Android 项目` + 检测结果，
  **不执行**任何命令
- 混合项目（含 android target 的多平台）→ 允许，但用例与前置必须限定
  Android 侧行为；非 Android 平台场景标注 SKIP
- 纯 iOS / 桌面 / Web / 服务端 / 无 UI 项目 → 拒绝（adb 黑盒 UI 测试
  对它们无意义；如需其他测试方式，由用户另行指定）
- 拒绝后不猜测、不硬跑、不降级为别的测试方式——明确告知用户

## generate 流程（理解项目是核心，按此顺序建立认知）

> **项目理解一次性现场完成，不落盘 project.md**——每次生成时读代码建立认知，
> 用完即弃；信息以代码为唯一权威，不维护可能过期的文档。

### 场景定位（带参数模式，先做这 4 步）

1. **解析场景**：把用户的中文场景描述映射到页面/功能（对照下方「场景定位表」；
   拿不准时读代码确认，不猜）
2. **读代码理解**：定位该场景涉及的页面实现（如 `ui/HostListScreen.kt`），确认
   入口、状态机、可断言特征（日志 tag / UI 文本 / 持久化值）、测试前置
3. **查已有覆盖**：读 `cases/*.md` 对应组，标出已覆盖与缺漏
4. **增量生成**：只补缺漏，追加到对应组或新建组（组字母按定位表建议，冲突顺延）

### 全量流程（无参数模式）

1. **技术栈定位**：读 build 配置/README，确认框架（Compose/XML/Flutter）与测试前置
2. **页面清单**：Android 侧从 manifest 找 Activity 入口；Compose 找根 Composable 与
   导航（tab/二级页/对话框）；逐个页面记录功能与状态
3. **状态与流程**：识别关键状态机（连接/登录/加载）、跨页面流程（表单提交→列表刷新）
4. **可断言特征**：找结构化日志（tag/级别）、UI 树可断言文本、持久化文件（shared_prefs）
5. **测试前置**：需要的服务器/账号/环境，标注可自动修复项与不可修复项
   （写入用例文件头部，供 run 自检）
6. 生成用例：按页面/功能分组写入 `.aiadb-test/cases/<group>.md`，模板见下
7. **覆盖度检查**：对照页面清单，确保每页至少一个用例、每状态机关键路径有覆盖；
   缺漏补写

### 两种模式共用的原则

- **先看后写**：任何时候都先读 `cases/` 与相关代码，不重复造轮子
- **用例必须可执行**：步骤具体到「点击哪里/输入什么/等多久」，预期绑定
  可断言特征（日志模式/UI 文本/持久化值），不写「应该正常」这种空话
- **环境敏感操作标注前置与恢复**：停服务器、改配置、清数据等破坏性操作
  必须带「恢复」步骤，并注明不可自动修复项
- 新增页面/功能 → 追加到对应组或新建组，保持编号规则

## 场景定位表（常见场景 → 页面/功能 → 组字母建议）

> 组字母仅建议；以 `cases/` 现状为准，已占用则顺延下一个字母。

| 场景关键词 | 页面/功能 | 建议组 |
|------------|-----------|--------|
| 连接、登录、认证、TOFU、公钥 | 连接建立/认证/主机密钥 | A |
| 网络、断网、重连、通知 | 网络故障/自动重连/后台通知 | B |
| 会话、会话列表、恢复、后台 | 会话生命周期/连接页列表/多 tab | C |
| Mosh、漫游、UDP | Mosh 协议 | D |
| SFTP、文件、上传下载 | SFTP 浏览/传输/恢复 | E |
| 主机、主机列表、搜索、批处理、增删改 | 首页/主机编辑页 | F |
| 终端、键盘、快速命令、粘贴 | 终端页工具栏/交互 | G |
| 设置、主题、语言、通知、诊断 | 设置页与二级页 | H |

## 用例模板（generate 必须按此格式产出，run 据此一致执行）

**以现有 `cases/*.md` 的实际格式为准**（先读一个已有文件再写，不发明新格式）；
当前基线格式如下：

文件头（每个新组文件必写，供 run 执行前自检）：

```markdown
# <场景>测试清单（自然语言）

> 执行者：AI agent（模拟器 + adb + logcat 断言）。
> 每个场景含：前置条件、操作步骤、预期行为（含日志断言模式）。
> 场景通过 = 预期日志出现且 UI 行为正确；报告 PASS/FAIL + 失败原因。

前置环境（所有场景）：

**AI 启动自检（每次执行场景前必跑，逐项确认，缺失自动修复或明确报错）：**

| # | 检查 | 命令 | 缺失处理 |
|---|------|------|----------|
| 1 | <检查项> | <检测命令> | <自动修复方式；不可修复则提示用户> |

自检通过后按 <组字母>→<末组字母> 顺序执行；场景内需要额外前置
（一次性配置）在场景描述中标注，首次执行时完成，后续复用。
```

用例（组标题 + 用例，步骤单行 `→` 序列，不写编号列表）：

```markdown
## A. 连接            # 组标题：<组字母>. <组名>

### A1 正常连接        # <组字母><序号> <场景名>
- 前置：<环境要求；无则"无">
- 步骤：<操作序列用 → 连接：冷启动 App → 点卡片 → 等待>
- 预期：<可断言特征；日志模式用反引号，日志先后用 →，UI 断言写可见行为>
  - 例：`I ssh: connect start ... attempt=0` → `I ssh: connected`；
    终端页显示，无错误 banner
- 恢复：<测试后环境恢复动作；无则"无">
```

要点：
- 编号规则 `<组字母><序号>`（A1、B2），组字母与「场景定位表」一致，冲突顺延
- 预期优先写日志断言（结构化 tag/级别 + 关键字段），其次 UI 文本/持久化值；
  日志模式一律反引号包裹
- 步骤必须具体到可执行（点击位置/输入内容/等待时长），不用「应该正常」
- 现有用例无「依赖」字段：靠组内顺序 + 自检表 + 「一次性配置」标注体现，
  不新增依赖字段

## 项目测试资产（<项目根>/.aiadb-test/）

| 文件 | 内容 |
|------|------|
| `cases/*.md` | 自然语言用例（按模板，run 的输入） |
| `results/` | run 产物：截图/日志/summary（不入库，gitignore 建议） |

- cases/ 已有文件 → 增量更新对应组，不重复造轮子
- 新增页面/功能 → 追加到对应组或新建组，保持编号规则
- 生成完成后提示执行方式：`ai-adb-run <组字母>`（如 `ai-adb-run C`）
