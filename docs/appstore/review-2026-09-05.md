## 提交前需要处理

### 1. 加密合规：重新确认声明

[Info.plist](../../iosApp/iosApp/Info.plist) 目前把
`ITSAppUsesNonExemptEncryption` 设为 `NO`，注释依据是 SSH / Mosh 使用标准协议。
但 iOS 构建包含 libssh2 / OpenSSL，Mosh 也有应用内的 AES / OCB 实现，
不能按“仅使用 Apple 操作系统提供的加密”填写。

在 App Store Connect 的 App 信息中，依据实际算法、用途和销售地区重新完成
加密文档问卷。标准算法本身不等于无需申报；Apple 对应用内标准加密以及法国
发行有单独的文档说明。确认结论后再同步 Info.plist；本次没有替发行人更改申报值。
参见 [加密文档要求](https://developer.apple.com/help/app-store-connect/reference/app-information/export-compliance-documentation-for-encryption/)
和 [确定并上传文档](https://developer.apple.com/help/app-store-connect/manage-app-information/determine-and-upload-app-encryption-documentation/)。

### 2. Agent 数据共享：补明确告知与同意流程

已核对的代码路径：

- [AgentScreen.kt](../../composeApp/src/commonMain/kotlin/dev/termish/ui/AgentScreen.kt)：读取服务商 API Key；创建会话和拉取模型时调用远程控制器。
- [AgentBridgeController.kt](../../composeApp/src/commonMain/kotlin/dev/termish/agent/AgentBridgeController.kt)：会话请求将 `provider.apiKey` 序列化并发送给所选服务器。
- [SettingsPrivacyScreen.kt](../../composeApp/src/commonMain/kotlin/dev/termish/ui/SettingsPrivacyScreen.kt)：有静态隐私说明，但所检查的 Agent 入口未发现与语音输入类似的明确数据共享确认步骤。

需要在首次共享之前说明目标主机、模型服务商以及可能发送的密钥、提示词、
上下文和附件，并取得明确同意；用户取消时不发送。主机或服务商变化时应重新
评估授权范围。隐私政策中也应明确“API Key 会为远程 Agent 使用而传给所选服务器”。
仅写“不经过 Termish 服务器”不足以解释这条数据流。

这是根据现有代码作出的提审风险判断，不代表已收到拒审。
Apple 对向第三方（包括 AI）共享个人数据要求事先告知并取得明确许可，见
[审核指南 5.1.2(i)](https://developer.apple.com/app-store/review/guidelines/#data-use-and-sharing)。
本次只检查材料，没有实现新的授权交互。

### 3. 隐私政策：修正删除说明，并核实隐私标签

[本地政策](privacy-policy.md)、线上 `/privacy/` 和应用内
[AppStrings.kt](../../composeApp/src/commonMain/kotlin/dev/termish/ui/AppStrings.kt)
仍将“卸载应用”概括为删除本地数据。iOS 凭据使用 Keychain，不能承诺仅卸载就
清除所有密钥；应指导用户先在 App 内删除保存的主机和服务商。
Apple 技术支持也说明卸载后 Keychain 可能留下状态，见
[DTS 说明](https://developer.apple.com/forums/thread/828110)。
所检查的主机、语音服务商和 Agent 服务商删除入口均调用了 `SecretStore.delete`。

建议三处同步采用以下意思，并在实际发布时更新政策日期：

> 你可以在 Termish 中删除保存的主机和服务商及其关联凭据。Android 可在系统设置中清除应用数据。iOS 钥匙串凭据可能在卸载后保留，卸载不能替代应用内的凭据删除。远程服务器或第三方服务持有的数据，需要向相应运营者申请删除。

当前 [PrivacyInfo.xcprivacy](../../iosApp/iosApp/PrivacyInfo.xcprivacy) 声明无追踪、
收集数据类型为空，并已包含 UserDefaults / FileTimestamp 的使用理由。
这份清单不能替代 App Store Connect 的 App 隐私问卷。填写前核实：

| 数据路径 | 当前可证实的事实 | 需要确认的申报依据 |
| --- | --- | --- |
| 主机配置和凭据 | 本地配置及系统凭据存储；连接时用于目标服务器认证 | 不把仅设备内存储等同于服务器端处理 |
| 语音 | 默认关闭；启用前有用途说明；录音发至配置的识别服务商 | 音频和转写结果是否在实时请求后保留、是否关联用户 |
| Agent | 所选服务器接收配置与内容，并可调用模型服务商 | API Key、提示词、上下文和附件的接收方及保留策略 |
| 日志 / 支持 | 用户可以主动导出并分享日志 | 实际支持流程是否接收和保存诊断或联系信息 |

不能只因为没有 Termish 自建后台或功能默认关闭，就直接选择“Data Not Collected”。
按 Apple 的收集定义、第三方处理方式和可选披露条件逐项判断；音频、用户内容、
诊断数据只是待评估类型，不在缺少保留策略证据时替发行人勾选。
参见 [App 隐私详情](https://developer.apple.com/app-store/app-privacy-details/)。

### 4. 付费：计划与当前构建不一致

对共享 Kotlin、iOS Kotlin / Swift 和依赖配置的检查未发现 StoreKit、购买流程
或 iOS 商品集成。当前 1.7.1 不能仅靠商店文案变成支持内购的版本。

若希望首发就通过内购收款，需要先完成该功能及商品审核材料；若本次先提交
现有功能，文案应保持与构建一致。下载价格、内购商品类型和价格还没有定稿，
本次未替用户作出商业决定；检查时项目采用闭源分发。2026-09-06 已按维护者决定恢复 MIT 开源，现行许可与商店文案见 LICENSE 和 submission.md。

### 5. 审核访问、联系人与销售范围：尚缺最终填写资料

现有材料只有本地演示环境，没有已验证的公网审核连接资料。需要为 SSH、Mosh、
SFTP、Herdr、Agent、远程画面与可选语音准备可复现的审核路径和所需测试访问权限。
真实账号、密码、密钥放在 App Store Connect 私有审核信息中，不进入 Git。

另需填真实审核联系人与电话、版权持有人、下载价格和发行地区。
年龄问卷应评估远程画面、网页访问和 Agent 等实际能力，不机械选择“全部无”，
也不因是终端工具而自动认定必须最高分级。
参见 [年龄分级定义](https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions/)。
